# Evidence collection within one shared deadline

Start from the supplied URL, preserving its path. Resolve robots at the origin, evaluate named crawler roles independently, and respect the audit collector's applicable rules. Fetch the requested page before inventories. Same-authority sitemap indexes are followed within three inventory requests; links and sitemap pages are sampled across inferred page types. The standalone collector defaults to 12 pages and 120 seconds; the timed agent audit requests 5 pages and 45 seconds. Both throttle to 2 requests/second. The collector uses only the standard library and its own identity. Cross-authority redirects are retained as untested coverage rather than followed. If an apex/www redirect prevents inspection, the agent may inspect the observed public destination after checking its own robots policy and reporting the changed scope; never bypass a block.

A robots 4xx is unavailable and permits collection; 5xx/network/incomplete policy stops collection. Missing robots is not a defect. The parser preserves matching rules, combines matching groups, uses the most specific path and prefers Allow for ties. Results describe policy rather than actual provider access. No request is made solely to impersonate a provider bot.

Preserve titles, language, canonical, HTTP indexing directives, same-page facts, structured data values, link labels/destinations and passage locators. Source HTML is not a rendered DOM: external CSS, responsive behavior, accessibility and actual UI state need a browser. Do not treat capped text, omitted structured-data payloads, timeouts or failed fetches as missing content. A request latency is not a Core Web Vital.

Target 280 seconds end to end, including instruction reading and evidence notes. Check elapsed time after collection and before each browser/search batch; start only a batch that fits the remaining collection window. By elapsed 120 seconds, stop all gathering and compose from existing evidence. Reserve 120 seconds for concise composition and the last 40 for validation and delivery. If a tool call crosses a boundary, do not start another collection call; name the resulting limits. A stage timeout never extends the original deadline. These instructions guide the host; the optional helper's timeout cannot enforce the host agent's end-to-end runtime.

Sample for the selected questions: supplied landing page, material decision/constraint page, and public next-step or proof destination. Reuse pages across tasks and stop when those questions have adequate support, rather than filling the page cap. A small sample must narrow the claims; it must not manufacture a missing-answer finding. Unfinished checks remain `not_checked` with the time/tool reason in the existing coverage fields, not a new schema property.

Read coverage and task-relevant page records first, not hundreds of kilobytes of inventory. An unrelated menu or sitemap page does not substitute for the supplied service's pricing, eligibility, support or next-step page. Count distinct inspected first-party pages once across static/rendered modes; record external corroborating documents separately. Query/locale/version states are journey observations, not automatically additional pages. Keep enough short source and action notes to reproduce a finding without transcribing entire pages into the report.

Render the supplied landing page and one or two task destinations when possible. Trace visitor journeys even if static text is complete. Compare specific material facts across source and rendered evidence when a question is unanswered or a shell/media trigger warrants it. Do not require all mobile/keyboard/performance tests in every five-minute run; record checks actually exercised.

Use the [retrieval protocol](retrieval-validation.md) for a compact off-site baseline. Reuse its source ledger in the entity skill. A small sample of searches cannot establish missing citations or a causal ranking factor.

## Finding gates

- Scope: claims about a template need representative pages and affected/checked counts. Site-wide claims require multiple templates or a directly observed policy whose scope is unambiguous.
- Intent: report a restriction in the context of the site's intended public task. Keep intentional privacy, training and utility-page indexing choices distinct from accidental discovery barriers.
- Material answers: inspect the relevant page and plausible supporting routes; a missing-in-sample answer needs a material task and exact inspection scope, not a keyword score. Judge each frozen required element. When all are supported and any apparent discrepancy is resolved, use `answered`; describe a localized ambiguity separately. Use `partial` only for a required element still unanswered or materially unresolved, and name that element. Do not add requirements after seeing a possible defect.
- Structured data: report invalid syntax or conflicting material values with evidence. Absence alone does not prove a defect or non-citation; a targeted opportunity may help a demonstrated ambiguity.
- Engagement: give steps, labels, destinations and a visible barrier. Aesthetic preferences, lack of personalization, and absent analytics are not defects.
- Media: show the decision-critical fact and the unavailable text equivalent in the tested reading mode. Decorative images and PDFs with readable text are not blanket failures.
- Trust: establish contradictions/identity collisions from opened sources. Search absence, missing dates and first-party-only facts are not enough.
